# Singularity example: code and checks

These implementation commands are for the agent. Teachers and students can start with the [repository prompt](../README.md#start-here) and [beginner's guide](START-HERE.md) without running them. The general workflow lives in `README.md`, `docs/START-HERE.md` and `skills/interactive-classroom-presentation/`; the app described below is one worked example. New activities should have their own project and appropriate checks.

Use Node.js 24 or later. The only runtime npm dependency is `qrcode-generator`. SQLite is provided by Node. The app does not call an AI service.

```sh
npm ci
npm test
npm run dev
```

The preview listens on `127.0.0.1:8787` with an in-memory database. `npm start` persists data under `data/`. For another port, set `PORT`. For deployment, set `HOST`, `DATABASE_PATH` and `PUBLIC_ORIGIN` in the service environment. No API key is required.

## Where things live

| Path | Purpose |
|---|---|
| `skills/interactive-classroom-presentation/` | The reusable agent skill: coaching approach, method cards, permitted-use check, activity design, rehearsal and templates. |
| `docs/START-HERE.md`, `docs/HOSTING.md` | General guidance for the user and agent, including costs and reuse. |
| `deck.json` | Speaker assignments, spoken text, actions, timing, sources and game facilitation cues. |
| `web/visuals.js`, `web/seminar-art.js` | Browser slide artwork; layout is code, not an automatic PPTX import. |
| `web/trajectory.js`, `web/outcomes.js` | Charts and explanations of actual decisions and results. |
| `web/participant-content.js` | Roles and round perspectives. |
| `web/game-notes.js`, `web/speaker.js` | Notes that follow game phases and private speaker navigation. |
| `web/walkthrough.js` | Skippable moderator guide; it does not mutate session state. |
| `game.mjs` | Pure scoring, aggregation and outcome logic, shared by browser and server. |
| `worker/api.mjs` | Room, vote and moderator API. |
| `server/` | Node HTTP adapter and SQLite persistence. |
| `drizzle/` | Ordered SQL migrations, including compatibility with earlier private versions. |
| `scripts/` | Build, browser checks and exports. |
| `tests/` | Node tests for rules, notes, persistence and access. |
| `presentation/` | Complete static PDF, PowerPoint and speaker text. |
| `web/assets/Speaker_*_V9.pdf` | Current individual speaker handouts. `V9` is the retained asset name, not a separate content source. |

Content changes can affect both the JSON and code-generated visuals. Update speaker notes, participant prompts, static worked examples and tests together. The game has no active policy ballot or opening/closing poll; some migration code recognises older saved formats so they are not silently reinterpreted.

## Browser checks and exports

Python 3.12 is a tested choice. Install the development packages and Chromium:

```sh
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
```

On Linux CI, use `python -m playwright install --with-deps chromium`. Keep the local preview running in a separate terminal, then run:

```sh
python scripts/export_presentation.py
python scripts/export_speaker_pdfs.py
python scripts/qa_browser.py
python scripts/qa_race_cooperation.py
python scripts/qa_apa.py
python scripts/qa_walkthrough.py
```

Export first: the speaker PDF checks expect the current generated files. `QA_BASE` can point to a different **test** deployment. Do not aim these scripts at a live class. They create synthetic rooms and delete their own rooms afterwards. Screenshots and temporary outputs go in ignored `output/`; some contain private test access links, so do not publish that directory.

The presentation exporter creates 17 pages: 15 browser slides plus two labelled worked examples. The PDF has searchable text. PowerPoint uses full-slide images to preserve the browser design and has editable speaker notes; individual visual elements are not native PowerPoint shapes. Edit the source and regenerate for visual changes.

`PUBLIC_URL` optionally sets the offline file's game hyperlink to your public deployment. Without it, the link points to this repository's setup instructions. It is never a private moderator link. A new session's live QR code is generated by the browser lobby.

## Testing scope

Node tests cover all 256 four-round strategy paths, counting, ties, absent voters, explicit moderator fallbacks, repeat actions, migrations and speaker permissions. Browser checks cover the complete classroom flow, 20 mobile role/round combinations, citations and the walkthrough. This is not a guarantee of capacity or accessibility conformance; rehearse on the intended hardware and network.

## Before sharing a fork

Use a fresh reviewed export. Exclude databases, backup archives, logs and private links. Scan the complete tracked history with a secret scanner and inspect PDF metadata, PPTX XML and links as well as source text. Use a private repository unless you have permission to publish the materials. [Academic boundary](ACADEMIC-USE.md) · [Security notes](../SECURITY.md)
