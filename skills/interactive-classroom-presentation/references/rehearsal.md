# Rehearsal checks

Choose the checks that fit the activity and record what you found and what is still untested. A visual the presenter controls does not need the same checks as a shared live game.

Share the checklist with the person. They can use it for their next talk on their own.

## The talk itself

- Can the person say the core message in one sentence, and does the talk open and close with it?
- Does the first minute have a hook (a question, a surprise or a case) and then a short signpost of where the talk is going?
- Does the ending pick up the opening, answering its question or returning to its case, instead of closing on "Any questions?"
- Does each slide carry one idea, with a headline that states it? See [the method cards](methods.md#assertionevidence-slides).
- Is there text on screen that the presenter will also read aloud? Cut it or turn it into a picture or key words.
- Are new terms introduced before they are used?
- Where are the long stretches of one-way listening? Is there a question, example or activity to change the mode?
- Is text readable from the back of the room, with enough contrast?
- Does the talk fit the time at a calm pace, including pauses, transitions and questions?
- Is it clear what is evidence, what is an example and what is a model assumption? Are sources cited?

## Learning and language in the activity

- Can a new participant explain the task and their first action from the first screen?
- Does every person have a meaningful way to take part, with an accessible alternative?
- Does the action require thinking about the talk's central idea?
- Can the presenter connect the result to evidence, reasoning or a clearly stated assumption?
- Are illustrative numbers and model outputs clearly different from real measurements?
- Does the discussion respond to what actually happened, including disagreement or uncertainty?
- Can a participant explain what they learned, not just describe what they clicked?
- Are instructions and notes natural to say aloud?

## Check the chosen format

| If the activity includes... | Check that... |
|---|---|
| Prediction and reveal | The answer is not shown early; evidence and explanation support the reveal. |
| Sorting or ranking | Categories make sense; alternatives work; ambiguous cases are explained fairly. |
| Marking a visual | Marks line up with the image on every screen size; labels and keyboard alternatives work. |
| Branching cases | Every intended path is reachable and gives consistent, plausible feedback; going back works clearly. |
| Simulation | Units, assumptions, calculations, limits and typical paths match an independent calculation. |
| Scores or competition | Each measure has a meaning; round and total scores agree; incentives fit the learning goal. |
| Roles or teams | Assignment is fair; roles can repeat if needed; each perspective and task is understandable. |
| Combined responses | Counting and display agree; ties and missing answers have clear rules; a majority is not overridden. |
| Shared live state | Repeated actions, late answers, disconnects and reconnects still give a consistent result. |

For small mechanics, check every path where feasible. For larger systems, use typical cases and rules that must always hold. Never invent real audience responses to fill a gap in testing.

## Running it on the day

- Test on the intended devices, with readable projection, keyboard focus and text contrast.
- With individual responses, try a small group and incomplete participation; check that the presenter can move on.
- If people join by QR code, scan the real code and check the alternative link or code entry.
- For online participation, open the link outside the presenter's computer and without their login. Check access requirements, how long the link lasts and shared results across separate devices. A local preview is not an external-access test.
- Keep private controls off the audience screen and check who can use them.
- A reset needs a deliberate action and affects only the intended activity.
- A walkthrough can be skipped, reopened and completed without changing the activity's state.
- Notes match the current phase and outcome; explanations of removed features are gone.
- If several people present, check each person's material and the handovers.
- Check exports, references, clipping and labels in any static version.
- Rehearse instructions, thinking time, interaction, discussion and transitions together.
- Practise the offline fallback. Check any backup and explain how hosting will stop.

Use separate test sessions for synthetic responses. Automated checks do not show that something is usable in a classroom, accessible, able to handle a given class size or good for learning. When possible, ask someone new to the topic to try the whole flow.
