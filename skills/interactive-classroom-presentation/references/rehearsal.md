# Rehearsal checks

Choose checks that fit the activity. Record evidence and remaining limits. A teacher-controlled visual does not need the same checks as a shared game.

## Learning and language

- Can a new participant explain the task and first action from the initial screen?
- Does every person have a meaningful way to contribute, with an accessible alternative?
- Does the action require thinking about the presentation's central idea?
- Can the presenter connect feedback to evidence, reasoning or a clearly stated assumption?
- Are illustrative numbers and model outputs distinguishable from real measurements?
- Does the discussion respond to what actually happened, including disagreement or uncertainty?
- Can a participant explain what they learned, rather than only describe what they clicked?
- Are instructions and notes natural to say aloud, with time for pauses and transitions?

## Check the chosen format

| If the activity includes... | Check... |
|---|---|
| Prediction and reveal | The answer is not exposed early; evidence and explanation support the reveal. |
| Sorting or ranking | Categories make sense; alternatives work; ambiguous cases are explained fairly. |
| Visual annotation | Marks align with the intended image across screen sizes; labels and keyboard alternatives work. |
| Branching cases | All intended paths are reachable and lead to consistent, plausible feedback; going back behaves clearly. |
| Simulation | Units, assumptions, calculations, boundaries and representative paths match an independent calculation. |
| Scores or competition | Each measure has a meaning; round and cumulative totals agree; incentives fit the learning goal. |
| Roles or teams | Assignment is fair; repeatable roles work; visible perspective and task are understandable. |
| Aggregated responses | Counting and display agree; ties and missing responses have explicit rules; a majority is not overridden. |
| Shared live state | Repeat actions, late responses, disconnects and reconnects preserve a consistent result. |

For small finite mechanics, check all paths where feasible. Use representative cases and invariants for larger systems. Never invent real audience responses to fill a test gap.

## Facilitation and delivery

- Test the intended devices, readable projection, keyboard focus and text contrast.
- If using individual responses, try a small group and incomplete participation; verify that the teacher can move on.
- If joining by QR, scan the actual session code and check the alternative link or code entry.
- For online participation, open the delivered link outside the presenter's local environment and without their login. Check access requirements, lifetime and shared results across separate clients. A local preview is not an external-access test.
- If there are private controls, check permission boundaries and keep them off the audience screen.
- If reset exists, require a deliberate action and affect only the intended activity.
- If there is a tutorial, skip, reopen and complete it without changing activity state.
- Check notes for the current phase and outcome; remove explanations of deleted features.
- Check each speaker's material and handover if more than one person presents.
- Check exports, references, clipping and labels for static examples where applicable.
- Rehearse instructions, thinking time, interaction, discussion and transitions together.
- Practise the offline fallback. Verify any backup and explain how hosting will stop.

Use separate test sessions for synthetic responses. Automated checks do not establish classroom usability, accessibility conformance, capacity for any class size or educational effectiveness. Try the complete flow with a person unfamiliar with the topic when possible.
