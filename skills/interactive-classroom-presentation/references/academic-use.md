# Check permitted use first

This is a decision guide for this workflow, abstracted from the institution guidance reviewed on 14 November 2026. It is not institutional approval. The institution has an official name. Current institutional and course instructions govern.

## Before reading teaching files

Use the conversation and existing project context to establish:

1. **Purpose:** Is this independent teaching or practice, or work for a graded assessment or any graded submission? A formative or ungraded submission still counts as a submission.
2. **Material:** Is it the user's own shareable content or permitted public material? Does it contain institution-provided teaching or assessment material, confidential information or personal data?
3. **Tools:** Are there applicable institutional or course restrictions on the proposed AI tools and data processing?

Do not ask again when these answers are already clear. If something material is unknown, ask for a short description of the intended use or provenance before opening the teaching files. Do not ask the user to upload restricted content so you can decide whether it is restricted.

| Finding | Action |
|---|---|
| Independent, ungraded use outside submissions, with own or permitted shareable material and no conflicting tool restriction | Briefly record that it fits this project's boundary and continue. Do not call it institutionally approved. |
| Assessment status, ownership or tool permission is unclear | Clarify the missing fact before analysing that material. General discussion of activity design can continue without it. |
| Graded work, a graded submission or institution-provided material intended for an external coding agent | Explain the relevant boundary and direct the user to the current institutional process or AI tutor. Do not continue with that content in this workflow or suggest relabelling it to avoid the restriction. |

For other institutions, check their applicable rules as well. Do not present the institution's policy as a universal rule.

## Principles behind the check

- **Approved tools matter.** The reviewed institution rules restrict submission tools. Paying for an external agent or enabling privacy controls does not make it an approved tool.
- **Check the exact Copilot experience.** The reviewed Microsoft Copilot fallback requires university sign-in and evidence of its data-protection indicator. Check current permission for the mode and model being used. A desktop installation is a convenience choice; GitHub Copilot is a different product. None of these checks expands this project's use boundary.
- **Material and data need permission.** Access to a course file does not automatically permit sending it to an external provider. Keep institutional and personal information out of public repositories.
- **Students retain responsibility.** They must understand, check and be able to explain their work. AI support must not replace the independent reasoning required by their course.
- **Disclosure and evidence matter.** Applicable rules may require a declaration, prompts, tool details and retained outputs. Follow the current requirements rather than treating this guide as a substitute.
- **Protected independent work stays independent.** Where a course requires a student-only analysis section, do not generate, rewrite or polish it with AI.
- **Rules can change.** Resolve uncertainty with current instructions or the institution's AI tutor before proceeding with restricted material.

The repository deliberately adopts a conservative boundary: ungraded, independently authored or permitted public material, outside graded submissions. It does not claim that the institution prohibits every use of AI in assessed work.

## Handling policy documents

When the user explicitly supplies local policy documents for this check, review only the relevant guidance and keep only the abstracted decision rules. Do not publish the original files, long extracts, signatures, student details or local paths. A policy review does not authorise processing other institutional material.
