# Activity brief template

Keep one brief per project, in the person's project folder, for example as `activity-brief.md`. Update it whenever a decision is agreed. It lets the person, or another agent, continue without starting again. Keep it short; leave a field empty rather than guessing.

```markdown
# Activity brief: [talk title]

Last updated: [date]

## The talk
- Presenter: [teacher / student / group]
- Audience: [who, how many, what they already know]
- Time: [length of the talk; time for the activity]
- Core message: [one sentence, in the presenter's words]
- Hard part: [the idea the audience is most likely to misunderstand]
- Story: [opening hook / open question / turning point / ending]

## Permitted use
- Result of the check: [e.g. own material, ungraded, outside any submission]
- Applicable rules checked: [conditions and result only; keep institutional names, source documents and private rule notes outside this repository]

## Changes to the talk (agreed)
- [method]: [before -> after] — [why]

## The activity
- Format and method: [e.g. predict, then reveal]
- Where it fits: [slide or moment]; role in the story: [opening hook / turning point / consolidation]
- What each person does: [one sentence]
- What they see afterwards: [feedback]
- Question for the discussion: [one or two]
- Setup: [paper / one laptop / shared link], hosting: [none / provider], cost agreed: [amount or none]

## Methods explained so far
- [method name]: [explained fully / mentioned briefly]

## Status
- Built: [what works]
- Tested: [what was checked, and how]
- Not yet tested: [what remains]
- Next step: [one line]
```
